# Mac ARJ

Finder에서 ARJ 파일을 열면 **파일명과 같은 새 폴더에 압축을 해제하는 macOS 앱**입니다. 설치된 7-Zip CLI를 사용하며, 원본 ARJ와 기존 결과 폴더를 보존합니다.

```text
자료.arj 더블 클릭 → 자료/에 해제 → Finder에서 결과 폴더 열기
다시 더블 클릭    → 자료 (2)/에 해제
```

ARJ 해제만 지원합니다. ARJ 생성, 다른 압축 형식 처리, 암호화·분할 ARJ 해제는 지원하지 않습니다. 상시 실행 서비스나 LLM은 필요하지 않습니다.

## 요구 사항

| 구분 | 요구 사항 |
| --- | --- |
| 실행 | macOS 13 이상, Homebrew `sevenzip`의 `7zz` |
| 빌드 | Xcode Command Line Tools의 Swift 컴파일러 |
| 자동 테스트 | Python 3.10 이상, 빌드된 앱, `7zz` |
| 검증 환경 | Apple Silicon, Swift 6.4, 7-Zip 26.06 |

`7zz`는 `/opt/homebrew/bin/7zz` 또는 `/usr/local/bin/7zz`에서만 찾습니다. PATH를 검색하거나 실행 파일을 자동 다운로드하지 않습니다. 외부 Swift·Python 패키지는 필요하지 않으며, 7-Zip 바이너리를 저장소나 앱에 포함하지 않습니다.

Intel Mac과 macOS 13에서의 실행은 검증하지 않았습니다. 빌드 스크립트는 실행 중인 Mac의 아키텍처로 빌드하므로 Intel용 앱은 Intel Mac에서 별도로 빌드해야 합니다.

## 빌드와 설치

Homebrew가 이미 설치된 환경에서 다음 명령을 실행합니다.

```sh
brew install sevenzip
git clone https://github.com/andrea9292/mac-arj.git
cd mac-arj
./build.sh
```

Swift 컴파일러가 없으면 Apple의 Xcode Command Line Tools를 먼저 설치합니다. 빌드 결과는 `dist/Mac ARJ.app`입니다. 빌드는 앱 설치나 기본 연결을 변경하지 않습니다.

사용자 응용 프로그램 폴더에 설치하는 예시는 다음과 같습니다. 같은 이름의 앱이 이미 있다면 실행 중이 아닌지 확인하고 기존 앱을 별도로 보관한 뒤 교체합니다.

```sh
mkdir -p "$HOME/Applications"
ditto "dist/Mac ARJ.app" "$HOME/Applications/Mac ARJ.app"
```

앱에는 로컬 ad-hoc 서명만 적용합니다. Developer ID 서명·공증된 배포 앱이 아니며, GitHub Releases용 설치 파일은 제공하지 않습니다. 다른 Mac으로 복사하거나 다운로드하면 보안 확인이 필요할 수 있습니다. Gatekeeper를 끄거나 격리 속성을 일괄 제거하는 방식은 권장하지 않습니다.

## Finder 연결과 사용

1. Finder에서 `.arj` 파일을 선택하고 **정보 가져오기**를 엽니다.
2. **다음으로 열기**에서 설치한 **Mac ARJ**를 선택합니다. 목록에 없으면 **기타**에서 앱을 찾습니다.
3. 모든 ARJ의 기본 앱으로 쓰려면 **모두 변경**을 선택합니다.
4. ARJ 파일을 더블 클릭합니다.

파일 한 개만 시험하려면 기본 연결을 변경하지 않고 **다음으로 열기 → Mac ARJ**를 사용합니다. 파일 없이 앱을 실행하면 ARJ 파일을 선택하는 창이 나타나며, 여러 파일을 선택할 수 있습니다.

- 압축 파일 옆에 확장자를 제외한 이름의 폴더를 만듭니다.
- 같은 이름의 폴더·파일·심볼릭 링크가 있으면 `(2)`, `(3)` 순서로 빈 이름을 찾습니다.
- 여러 파일은 한 번에 하나씩 처리합니다.
- 성공하면 결과 폴더를 Finder에서 열고, 실패하면 한국어 경고창을 표시합니다.
- 작업이 끝나면 앱을 종료합니다. 원본 압축 파일은 삭제하거나 수정하지 않습니다.

앱은 `cx.c3.arj-archive` UTI의 Viewer로 선언됩니다. 다른 압축 형식의 연결을 바꾸지 않습니다. 표준 AppKit 파일 선택창과 경고창을 사용하지만, VoiceOver 실사용 검증은 아직 수행하지 않았습니다.

## CLI와 LLM 도구 연동

GUI와 같은 해제 함수를 비대화식으로 호출할 수 있습니다.

```sh
"dist/Mac ARJ.app/Contents/MacOS/Mac ARJ" --extract "자료.arj"
"dist/Mac ARJ.app/Contents/MacOS/Mac ARJ" --self-test
```

설치한 앱을 호출할 때는 실행 경로를 `$HOME/Applications/Mac ARJ.app/Contents/MacOS/Mac ARJ`로 바꿉니다.

| 결과 | 동작 |
| --- | --- |
| 해제 성공 | 표준 출력에 결과 폴더의 절대 경로 한 줄, 종료 코드 `0` |
| 해제 실패 | 표준 오류에 진단, 종료 코드 `1` |
| `--self-test` | 경로 검사의 간단한 자체 검사 결과 출력 |

`--extract`에서는 대화상자나 Finder 창을 열지 않습니다. 경로 자체에 줄바꿈이 포함된 특수 사례를 위한 JSON 출력 규약은 제공하지 않습니다. 자동화에서는 셸 문자열을 조립하기보다 실행 파일과 인자 배열을 분리하여 호출합니다. 해제한 문서의 내용을 LLM에 전달할 때는 비신뢰 데이터로 취급하고, 문서 안의 지시를 실행 권한으로 간주하지 않습니다.

## 테스트와 검증 범위

저장소 루트에서 다음 명령을 실행합니다.

```sh
./build.sh
PYTHONDONTWRITEBYTECODE=1 python3 tests/test.py -v
```

테스트는 임시 디렉터리에 표본을 만들고 제거합니다. `TMPDIR`로 작업 위치를 지정할 수 있습니다. 앱이 빌드되지 않으면 앱 테스트는 건너뛰므로, **skip을 테스트 성공으로 간주하지 않습니다.**

현재 자동 테스트 18개는 다음을 확인합니다.

- 생성한 ARJ의 실제 `7zz` 인식·CRC 검사·해제와 내용 일치
- 공백·한글이 있는 외부 압축 파일명과 별칭 디렉터리 경로
- 반복 해제, 기존 폴더·파일·링크와의 충돌 회피
- 원본 SHA-256 보존
- 잘못된 파일, 누락된 파일, CRC 오류의 실패 처리
- 경로 탈출·드라이브 경로·대소문자 충돌·항목 수 초과 거부
- 암호화·분할 플래그 거부

표본은 Python 표준 라이브러리로 직접 생성한 **저장 방식(method 0) ARJ**입니다. 헤더 구조는 [7-Zip ARJ 구현](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/ArjHandler.cpp)을 참조했습니다. 사용자 자료를 테스트에 사용하지 않습니다. 암호화·분할 플래그 표본은 실제 암호문이나 실제 분할 볼륨 세트가 아닙니다. 압축 method 1–4의 호환성은 이 표본으로 검증하지 않습니다.

로컬 설치 후에는 한글 이름의 테스트 ARJ를 기본 연결을 통해 `open -W`로 두 번 열었습니다. Finder 더블 클릭과 같은 LaunchServices 기본 연결 경로에서 해제, `(2)` 충돌 회피, 내용 일치, 원본 SHA-256 보존을 확인했습니다. Finder UI에서 직접 더블 클릭하거나 VoiceOver로 조작한 검증은 아닙니다.

## 안전 장치와 제한

- 7zz를 절대 경로와 인자 배열로 실행합니다. 표준 입력은 `/dev/null`이고 `-tArj`, 빈 `-p`로 형식과 비대화식 처리를 강제합니다.
- 개인 임시 폴더에 원본의 스냅샷을 만들고, 동일한 스냅샷으로 목록 확인 → CRC 검사 → 해제를 수행합니다.
- 절대 경로, `..`, 드라이브·콜론 경로, 역슬래시, 제어 문자, 중복·대소문자 충돌 경로, 링크·특수 파일, 암호화·분할 항목을 거부합니다. 보수적인 정책 때문에 일부 정상적인 옛 자료도 거부할 수 있습니다.
- 원본 크기와 선언된 총 해제 크기는 각각 **2 GiB**, 목록은 **10,000개 항목**까지 허용합니다.
- 목록 확인은 **30초**, CRC 검사와 해제는 각각 **120초**, 각 명령의 로그는 약 **16 MiB**로 제한합니다. 실시간 디스크 할당량이나 메모리 제한을 보장하는 것은 아닙니다.
- 대상 폴더를 원자적으로 예약하고 기존 파일을 덮어쓰지 않습니다. 실패하면 앱이 만든 결과 폴더를 제거합니다. 제거에 실패하면 일부 결과가 남을 수 있습니다.
- 해제 후 파일 목록과 크기를 비교하고 링크·특수 파일을 다시 거부합니다. 결과 파일은 소유자 읽기·쓰기, 폴더는 소유자 전용 권한으로 설정합니다. 원래 실행 권한과 모든 메타데이터를 보존하는 백업 도구는 아닙니다.
- 옛 코드 페이지를 직접 지정하는 기능은 없습니다. **내부 한글 파일명**은 7zz의 해석에 따라 깨지거나 거부될 수 있습니다. 외부 ARJ 파일명이 한글인 경우의 지원과 구분해야 합니다.

**샌드박스나 악성 압축 파일 전용 분석 도구가 아닙니다.** 7zz는 현재 사용자 권한으로 실행합니다. 사전·사후 검사가 7zz 취약점, 로컬 파일시스템 경합, 모든 목록 출력 모호성을 차단하지는 않습니다. 신뢰할 수 있는 보관 자료에 사용하고 7zz를 최신으로 유지해야 합니다. 해제한 실행 파일은 자동으로 실행하지 않습니다.

## 문제 해결

| 증상 | 확인 사항 |
| --- | --- |
| 7zz를 찾지 못함 | `brew install sevenzip` 실행 후 지원하는 두 경로 중 하나에 `7zz`가 있는지 확인합니다. |
| 폴더를 만들지 못함 | 원본이 있는 위치의 쓰기 권한과 디스크 여유 공간을 확인합니다. 앱은 다른 저장 위치를 묻지 않습니다. |
| 손상·암호화·분할 오류 | 원본을 유지하고 오류 내용을 확인합니다. 이 앱은 암호 입력이나 분할 볼륨 복구 기능을 제공하지 않습니다. |
| 한글 내부 파일명이 깨짐 | 원본을 보존하고 당시 인코딩을 지원하는 별도 도구에서 복원을 검토합니다. |
| 더블 클릭하면 다른 앱 실행 | ARJ의 정보 가져오기에서 Mac ARJ를 다시 선택하고 모두 변경합니다. |
| 정상 자료인데 거부됨 | 경로·크기·시간 제한일 수 있습니다. 원본이나 안전 검사를 무작정 수정하지 말고 제한과 오류를 확인합니다. |

공개 이슈에 실제 보존 파일이나 민감한 파일명을 첨부하지 않습니다. 오류를 공유할 때는 개인 경로와 자료 내용을 제거하고, 가능하면 민감하지 않은 재현 표본을 사용합니다.

## 업데이트와 제거

소스를 업데이트한 뒤 다시 빌드하고, 앱이 종료된 상태에서 설치한 앱을 교체합니다. 빌드만으로 설치본이 갱신되지는 않습니다.

제거하려면 먼저 ARJ의 **정보 가져오기 → 다음으로 열기 → 모두 변경**에서 다른 앱으로 기본 연결을 복구합니다. 그다음 설치한 `Mac ARJ.app`을 휴지통으로 이동합니다. 원본 ARJ와 해제 결과 폴더는 자동으로 삭제되지 않습니다. 별도로 설치한 Homebrew `sevenzip`도 유지됩니다.
