# Mac ARJ

macOS에서 ARJ 압축 파일을 같은 위치의 새 폴더에 해제하는 작은 AppKit 앱이다. 원본 압축 파일을 보존한다. 기존 폴더가 있으면 `이름 (2)`, `이름 (3)` 순서로 새 폴더를 만든다. 다른 압축 형식은 지원하지 않는다.

## 요구 사항과 빌드

- macOS 13 이상과 Xcode Command Line Tools의 Swift 컴파일러가 필요하다.
- Homebrew의 `sevenzip` 패키지(`7zip` 별칭)가 필요하다. `7zz`는 `/opt/homebrew/bin/7zz` 또는 `/usr/local/bin/7zz`에서만 찾는다. PATH를 검색하거나 실행 파일을 내려받지 않는다.
- 외부 Swift 패키지를 사용하지 않는다.

```sh
brew install sevenzip
./build.sh
```

빌드 결과는 `dist/Mac ARJ.app`이다. 빌드 스크립트는 로컬 ad-hoc 서명을 수행하며, 앱 설치나 기본 연결 변경은 하지 않는다. 배포용 Developer ID 서명·공증은 포함하지 않는다. Apple Silicon 환경에서 Swift 6.4 및 7-Zip 26.06으로 빌드·통합 테스트했다. Intel에서는 해당 Mac에서 다시 빌드해야 한다.

## 설치와 사용

1. 빌드한 앱을 응용 프로그램 폴더로 복사한다.
2. Finder에서 `.arj` 파일의 **정보 가져오기 → 다음으로 열기**에서 Mac ARJ를 선택한다. 원하는 경우 **모두 변경**으로 ARJ 기본 앱을 바꾼다. 다른 압축 확장자의 연결은 바꾸지 않는다.
3. 파일을 더블 클릭하거나 **다음으로 열기 → Mac ARJ**를 선택한다.

파일 없이 앱을 실행하면 여러 ARJ 파일을 고를 수 있는 파일 선택창이 나타난다. Finder로 전달된 여러 파일은 한 번에 하나씩 처리한다. 성공하면 결과 폴더를 Finder에서 열고, 실패하면 한국어 기본 경고창을 표시한다. 작업이 끝나면 앱을 종료한다. UI는 표준 AppKit 파일 선택창과 경고창을 사용하며 VoiceOver가 읽을 수 있는 제목·본문·버튼을 제공한다.

앱은 `cx.c3.arj-archive` UTI를 가져온 형식으로 선언하고 Viewer 역할로 등록한다. 자체 UTI를 새로 내보내거나 모든 압축 파일을 가로채지 않는다.

## 자동화와 테스트

```sh
"dist/Mac ARJ.app/Contents/MacOS/Mac ARJ" --extract "자료.arj"
"dist/Mac ARJ.app/Contents/MacOS/Mac ARJ" --self-test
PYTHONDONTWRITEBYTECODE=1 python3 tests/test.py -v
```

`--extract`는 대화상자나 Finder 창 없이 동작한다. 성공하면 표준 출력에 결과 폴더의 절대 경로 한 줄을 쓰고 종료 코드 0을 반환한다. 실패하면 표준 오류에 진단을 쓰고 종료 코드 1을 반환한다. GUI와 같은 해제 코드를 사용한다.

테스트는 Python 표준 라이브러리로 직접 만든 결정적인 **저장 방식(method 0) ARJ**를 사용한다. 다운로드한 압축 파일이나 사용자의 실제 자료는 사용하지 않는다. 헤더 구조는 [7-Zip ARJ 구현](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/ArjHandler.cpp)을 참조했다. 생성한 파일을 실제 `7zz`로 인식·검사·해제하고 바이트를 비교한다. 파일명 충돌, 공백·한글이 있는 외부 파일명, 별칭 경로, 원본 SHA-256 보존, 잘못된 파일, CRC 오류, 경로 탈출, 암호화·분할 플래그를 테스트한다. 암호화·분할 플래그 표본은 실제 암호문이나 실제 분할 볼륨 세트가 아니다. 압축 method 1–4의 공개 표본과 VoiceOver 실사용 검증은 이 자동 테스트에 포함하지 않는다. 앱이 빌드되지 않으면 앱 테스트는 명시적으로 건너뛴다.

로컬 설치 검증에서는 macOS의 기본 ARJ 연결을 이 앱으로 지정하고, `open -W`로 한글 이름의 테스트 파일을 두 번 열었다. Finder 더블 클릭과 같은 LaunchServices 기본 연결 경로에서 해제, `(2)` 충돌 회피, 내용 일치 및 원본 SHA-256 보존을 확인했다. Finder UI에서 직접 더블 클릭하거나 VoiceOver로 조작한 검증은 아니다.

## 안전 장치와 제한

- 7zz는 셸 없이 절대 실행 경로와 인자 배열로 실행한다. 표준 입력은 `/dev/null`이며 `-tArj`, 빈 `-p`로 형식과 비대화식 처리를 강제한다.
- 먼저 개인 임시 폴더로 복사한 스냅샷에서 `7zz l -slt -ba`로 목록을 검사하고 `7zz t`로 CRC를 검사한 다음 해제한다.
- 절대 경로, `..`, 드라이브·콜론 경로, 역슬래시, 제어 문자, 중복·대소문자 충돌 경로, 링크·특수 파일, 암호화·분할 항목을 거부한다. 보수적인 경로 정책 때문에 일부 정상적인 옛 파일도 거부할 수 있다.
- 원본 크기와 선언된 총 해제 크기는 각각 2 GiB, 목록은 10,000개 항목까지 허용한다. 목록 처리는 30초, CRC 검사와 해제는 각각 120초까지 허용하며, 각 명령의 로그는 약 16 MiB로 제한한다. 제한은 실시간 디스크 할당량이나 메모리 제한을 뜻하지 않는다.
- 대상 폴더는 `mkdir`로 원자적으로 예약한다. 기존 폴더·파일·링크와 충돌하면 다음 이름으로 시도한다. 기존 파일을 덮어쓰지 않는다. 해제 실패 시 앱이 만든 결과 폴더를 제거하며, 제거 실패 시 일부 파일이 남을 수 있다.
- 해제 후 일반 파일 목록과 크기를 비교하고 링크·특수 파일을 다시 거부한다. 결과 파일은 읽기·쓰기 전용, 폴더는 소유자 전용 권한으로 설정한다. 원래 실행 권한이나 모든 메타데이터를 보존하는 백업 도구는 아니다.
- ARJ 내부 파일명의 오래된 코드 페이지를 직접 지정하는 기능은 없다. 한글 내부 파일명은 7zz의 해석에 따라 달라지거나 거부될 수 있다.
- **샌드박스나 악성 압축 파일 전용 분석 도구가 아니다.** 7zz는 현재 사용자 권한으로 실행한다. 사전 검사와 사후 검사로 7zz의 취약점, 로컬 공격자의 파일시스템 경합, 모든 목록 출력 모호성을 완전히 차단하지 못한다. 신뢰할 수 있는 보관 자료에 사용하고 7zz를 최신으로 유지해야 한다.
